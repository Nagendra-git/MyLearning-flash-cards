Hash Map

Stores data as key -> Value pairs.
Part of the Java Collection Framework.
Implements the Map interface.
Located in java.utils package.
Declaration:
    Map<String, Integer> map = new Hashmap<>();

Important Methods

| Method                            | Purpose                 |
| --------------------------------- | ----------------------- |
| `put(key, value)`                 | Insert/Update           |
| `get(key)`                        | Retrieve value          |
| `getOrDefault(key, defaultValue)` | Return value or default |
| `containsKey(key)`                | Check key               |
| `containsValue(value)`            | Check value             |
| `remove(key)`                     | Remove entry            |
| `replace(key, value)`             | Replace value           |
| `size()`                          | Number of entries       |
| `isEmpty()`                       | Check empty             |
| `clear()`                         | Remove all entries      |
| `keySet()`                        | Returns all keys        |
| `values()`                        | Returns all values      |
| `entrySet()`                      | Returns key-value pairs |

Iteration

for(Map.Entry<String, Integer> entry : map.entrySet()){
    System.out.println(entry.getkey() + " "+ entry.getValue());
}

Time Complexity

| Operation     | Average | Worst            |
| ------------- | ------- | ---------------- |
| put()         | O(1)    | O(n) / O(log n)* |
| get()         | O(1)    | O(n) / O(log n)* |
| remove()      | O(1)    | O(n) / O(log n)* |
| containsKey() | O(1)    | O(n) / O(log n)* |
* In Java 8+, buckets with many collisions can become balanced trees, making lookups in those buckets O(log n) instead of O(n).

Null Rules

| Feature              | Allowed |
| -------------------- | ------- |
| One null key         | ✅       |
| Multiple null values | ✅       |

Ordering :HashMap does NOT maintain insertion order.

Never depend on iteration order.

Internal Working
Key
 ↓
hashCode()
 ↓
Bucket Index
 ↓
Store Entry

Formula :Bucket = hashCode % Capacity
(Conceptually. The actual JDK implementation uses a bitwise calculation based on the table size.)

Collision : Two different keys may go to the same bucket.
Bucket 5
Java → 100
Spring → 200
This is called a collision.

Collision Handling
Java 7
Bucket
↓
Linked List
Java 8+
Bucket
↓
Linked List
↓
Red-Black Tree
when the number of entries in a bucket becomes large.

Initial Capacity
16
Default Load Factor
0.75

Resize happens when
size > capacity × loadFactor
Example
16 × 0.75 = 12
After 12 entries,
Capacity becomes
32
