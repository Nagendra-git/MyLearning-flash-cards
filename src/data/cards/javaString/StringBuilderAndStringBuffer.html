StringBuilder And StringBuffer

Both StringBuilder and StringBuffer are mutable classes used to modify strings efficiently. Unlike String, they do not create a new object for every modification.

StringBuilder

    Mutable
    Faster
    Not thread-safe
    Introduced in Java 5

    Why is StringBuilder faster?
    Its methods are not synchronized.
    public StringBuilder append(String str)
    No locking overhead.
    Internal Capacity:-16
    Capacity with Initial String
        StringBuilder sb = new StringBuilder("Java");
        16 + length("Java")
        16 + 4 = 20
    How Capacity Grows
        (newCapacity = oldCapacity × 2) + 2
        Append more than 16 characters.
        16 × 2 + 2 = 34

StringBuffer

    Mutable
    Thread-safe
    Slower than StringBuilder
    Introduced in Java 1.0

    Why is StringBuffer thread-safe?
    All its methods are synchronized.
    Example
    public synchronized StringBuffer append(String str)
    Only one thread can modify the object at a time.

Comparison

| Feature         | String                    | StringBuilder | StringBuffer |
| --------------- | ------------------------- | ------------- | ------------ |
| Mutable         | ❌ No                     | ✅ Yes       | ✅ Yes       |
| Thread-safe     | Yes (immutable)           | ❌ No         | ✅ Yes      |
| Performance     | Slow (many modifications) | Fast          | Moderate     |
| Introduced      | Java 1.0                  | Java 5        | Java 1.0     |
| Synchronization | Not needed                | No            | Yes          |
